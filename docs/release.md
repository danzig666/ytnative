# Releasing ytnative

## What a release is

A GitHub release `vX.Y.Z` with four files, all produced by `.github/workflows/release.yml`:

| File | What it is for |
|---|---|
| `io.github.danzig666.ytnative_X.Y.Z_arm.ipk` | the package (stripped binary + `crates/app/pkg/*`) |
| `io.github.danzig666.ytnative.manifest.json` | webOS Homebrew Channel package manifest (id, version, `type: native`, title, `iconUri`, `sourceUrl`, `rootRequired: false`, `ipkUrl`, `ipkHash.sha256`, `ipkSize`) |
| `repo.json` | a one-package custom-repository index pointing at the newest manifest |
| `ytnative-X.Y.Z.debug` | the unstripped twin of the shipped binary, for symbolizing crash logs (docs/debugging.md) |
| `SHA256SUMS` | checksums of the above |

The Homebrew Channel checks the IPK's sha256 against `ipkHash` **on the TV**; nothing else signs
the package. Never replace a release asset by hand: re-run the workflow (or cut a new version) so
the manifest is regenerated together with the IPK.

## How the build works without a TV

The app links against the TV's `libSDL2`, `libGLESv2`, `libluna-service2`, ... by soname. Instead
of LG's binaries (which cannot be committed or downloaded in CI), `crates/app/build.rs` links
against **stub libraries** generated by `tools/gen-stubs.py` from the checked-in symbol lists
`ci/symbols/<soname>.txt` (names, kinds and data sizes only). The stubs are never shipped; on the
TV the real libraries are loaded. This is also what makes the binary GPU-neutral: it names
`libGLESv2.so.2`, and the TV's real libGLESv2 pulls in whatever driver that set has (libmali today).

Guards:

* `ci/expected-dt-needed.txt`: every `cargo xtask build` compares the binary's DT_NEEDED with it.
  A new library dependency fails the build until the list is updated on purpose.
* `cargo xtask symcheck` / `cargo xtask fwcompat` (dev PC, needs real TV libraries): every import,
  with its symbol version, exists on the TV. Run before tagging.
* The symbol lists are refreshed from a TV with `cargo xtask pull-sysroot` (needs the TV) then
  `cargo xtask stub-symbols`. They are full export lists, so new calls into an already-linked
  library link without a refresh; a refresh is only needed for a new library or a new firmware.

## Cutting a release

1. Bump `version` in `crates/app/pkg/appinfo.json` (the workflow refuses a tag that does not match
   it). The Homebrew Channel compares versions as strings for "update available", so always bump.
2. On the dev PC, with the TV's libraries in `sysroot/`:
   ```bash
   cargo test -p yt-core
   cargo xtask ipk             # builds, strips, checks DT_NEEDED, packages
   cargo xtask symcheck        # every import resolves on this TV
   cargo xtask fwcompat sysroots/   # ...and on every other snapshot you keep (docs/debugging.md)
   cargo xtask install && cargo xtask run   # smoke test on the TV
   ```
3. Commit, then tag and push the tag:
   ```bash
   git tag -a v0.2.0 -m "ytnative 0.2.0"
   git push origin v0.2.0
   ```
   The `release` workflow builds on `windows-latest` (Rust msvc host + zig from the `ziglang`
   wheel, stub-only link), runs the yt-core tests, writes the IPK, manifest and `repo.json`,
   uploads them as workflow artifacts and creates the GitHub release.
4. A dry run without a release: Actions > release > "Run workflow" (workflow_dispatch) uploads the
   same files as artifacts only.

`cargo xtask release-manifest [ipk-url] [out]` produces the manifest and `repo.json` locally from
`target/ipk/`. By default `ipkUrl` is the absolute, tag-pinned
`https://github.com/danzig666/ytnative/releases/download/vX.Y.Z/<ipk>`, so a manifest can never
point at a different IPK than the one it hashes; `YTNATIVE_ICON_URI` overrides the icon URL (it
must be https and answer 200).

## Installing

### Homebrew Channel (rooted or not; `rootRequired: false`)

Custom repository (works today, no review needed):

1. Install the [webOS Homebrew Channel](https://github.com/webosbrew/webos-homebrew-channel)
   (it needs Developer Mode or root).
2. Homebrew Channel > Settings > **Add repository**, URL
   `https://github.com/danzig666/ytnative/releases/latest/download/repo.json`.
3. ytnative appears in the list; install it. Updates appear when a newer release is published.

Not yet verified on a TV: that the Channel follows GitHub's redirect from `releases/latest/download/`
to the asset host. If it does not, host `repo.json` (and optionally the manifest) on GitHub Pages
and add that URL instead; the manifest's `ipkUrl` is absolute, so it can live anywhere.

Official listing (later): fork `webosbrew/apps-repo`, add `packages/io.github.danzig666.ytnative.yml`
(title, iconUri, `manifestUrl: https://github.com/danzig666/ytnative/releases/latest/download/io.github.danzig666.ytnative.manifest.json`,
category, `pool: main`, description) and open a PR. Its CI resolves the binary's DT_NEEDED and
imports against its firmware symbol database; `cargo xtask fwcompat` is the local equivalent.

### Developer Mode (no Homebrew Channel)

1. Enable Developer Mode on the TV (LG Developer Mode app; the session must be renewed every
   50 hours unless the TV is rooted).
2. Download the `.ipk` from the release and install it with LG's CLI:
   `ares-install --device <tv> io.github.danzig666.ytnative_X.Y.Z_arm.ipk`
   (or, from a checkout with SSH set up, `cargo xtask install`).
3. Launch it from the launcher, or `ares-launch --device <tv> io.github.danzig666.ytnative`.
